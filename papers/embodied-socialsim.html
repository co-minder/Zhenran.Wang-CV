Embodied-SocialSim

A Device-Ready Agent Framework for Embodied Robots

Zhenran Wang†∗, Zhonghan Bian†, Jinsong Li, Zhangyang Qi∗

这项工作以 Agnes Harness 为 Agent 运行和治理骨架，连接设备状态、视觉/YOLO、ROS2、MHS/MOS、规划、执行、轨迹与恢复机制；在此框架上构造可控社会仿真，用来检验机器人在多轮关系、规范和协作情境中的感知、决策与行动。主线是设备可接入的具身 Agent 框架，社会仿真是研究环境，而不是社会事件预测项目。

01 / SYSTEM PROBLEM

机器人 Agent 不只要“说得通”，还要“接得上、跑得稳、能复盘”

纯文本 Agent 的一次调用可以结束于一段自然语言，但具身机器人必须持续读取设备状态、理解视觉观测、提出工具调用、等待动作结果，并在中断、传感器异常或计划失败后恢复。如果状态、审批和轨迹分散在不同脚本里，研究者无法判断失败来自视觉、规划、控制还是社会情境理解。

Embodied-SocialSim 试图把这些过程放入一个有明确职责边界的运行框架：Harness 负责任务上下文和执行治理，设备协议负责状态与观测，Agent 负责解释和规划，控制器负责实时安全；社会仿真则提供可重复的复杂行为场景。

02 / SYSTEM ARCHITECTURE

四个工程层，外加一条不可越过的安全边界

L1Device + vision

相机、位姿、地图、健康状态和 YOLO 等可替换感知模块。

L2ROS2 / MHS-MOS

把持续观测、动作请求和状态反馈组织成可记录通道。

L3Agnes runtime

上下文、审批、工具执行、事件账本、恢复和会话历史。

L4Agent + social env

感知、规划、执行，在关系和规范组成的环境中循环。

模块负责什么不负责什么
Agnes Harness任务状态、工具审批、执行记录、证据、恢复与可复盘会话不替代机器人本体和实时控制器。
MHS / MOSMHS 传递命令与动作；MOS 提供设备和传感器观测不把高层 Agent 直接变成安全控制回路。
ROS2用 node、topic、service、action 组织模块通信不自动保证上层规划正确。
设备控制器实时运动、互锁、急停、断联后的本地接管不由 LLM 文本替代。

03 / RESEARCH EVALUATION

先验证系统可靠性，再讨论社会行为质量

评测层核心问题可记录指标
设备接入状态、命令和观测是否能双向流动？延迟、丢包、重连、动作确认、协议错误。
视觉 / 状态Agent 是否从观测提取可用环境状态？检测准确率、状态一致性、遮挡和异常观测。
规划 / 执行计划是否落地，失败后是否恢复？任务成功率、重试次数、失败归因、轨迹完整性。
社会行为关系、规范和群体反馈是否改变行动？规范遵循、协作收益、冲突处理、社会状态更新。
迁移仿真结论能否迁移到更接近真实的环境？仿真—设备差异、可迁移行为、未覆盖风险。
实验逻辑：用 Planning Oracle 或固定导航能力拆分“机器人没有走到”和“机器人没有理解社会证据”；先锁定底层执行，再比较社会推理和协作策略。

04 / SOCIAL SIMULATION AS A RESEARCH ENVIRONMENT

社会仿真是让具身行为变复杂、可控且可重复的实验场

环境状态

  • 机器人与角色：位置、能力、任务和可见信息；
  • 关系：信任、协作、冲突和历史互动；
  • 规范：允许/禁止的行动、角色期待和情境规则；
  • 事件：观察到的变化、请求、阻碍和群体反馈。

行为循环

  1. 机器人从视觉和设备通道获得观测；
  2. Harness 记录状态和行动上下文；
  3. Agent 生成计划并请求工具执行；
  4. 环境返回结果，更新关系、规范和任务状态；
  5. 轨迹用于失败归因、恢复和下一轮评测。

项目定位：Embodied-SocialSim 的社会环境用于检验具身 Agent 的感知、规划、协作和规范遵循；SocietyBench 负责独立的社会事件预测评测。

05 / OUTPUT AND SAFETY

项目成果与设备安全边界

交付成果

  • Agnes Harness 运行和治理骨架的职责划分；
  • ROS2、MHS/MOS、视觉、规划和执行模块的接口设计；
  • 社会仿真环境、角色关系和多轮反馈机制；
  • 分层评测、失败归因和恢复机制的完整协议。

系统安全职责

  • 实时运动、互锁、急停和断联接管由设备控制器负责；
  • 仿真行为和设备行为分别记录、分别解释；
  • Harness 负责高层状态、审批、轨迹和恢复；
  • Agent 规划通过声明能力和工具通道进入执行链路。

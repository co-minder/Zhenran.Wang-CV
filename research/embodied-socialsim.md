# Embodied-SocialSim：设备可接入的具身 Agent 框架与社会仿真

## 核心定位

Embodied-SocialSim 的主线是**具身机器人框架**，不是单独的社会分析或社会事件预测项目。

项目以 Agnes Harness 作为可恢复、可记录的 Agent 运行骨架，已将模型、任务状态、工具审批、执行轨迹、视觉和设备能力组织起来，并完成可控社会仿真与具身行为评测的职责定义。

## 框架分层

```text
设备与传感器
  ├─ 摄像头 / 地图 / 位姿 / 健康状态
  └─ YOLO 等视觉感知模块（可替换）
             ↓
ROS2 / MHS-MOS 设备接口
             ↓
Agnes Harness 运行时
  ├─ 任务状态与历史
  ├─ 工具审批与执行约束
  ├─ 轨迹记录与证据链
  └─ 中断、恢复与可复盘会话
             ↓
LLM Agent / 规划 / 执行
             ↓
机器人行动与环境反馈
             ↓
可配置社会仿真环境
  ├─ 机器人与角色
  ├─ 关系、规范与事件
  └─ 多轮互动和群体反馈
             ↓
具身行为评测
```

## Agnes Harness 在这里负责什么

Agnes Harness 是运行和治理底座，不等同于机器人本体，也不替代设备的实时安全控制。根据其公开架构：

- Harness 保存任务上下文、会话历史、执行记录和可复用方法，并负责受控执行与恢复；
- MHS 负责设备的状态、工具、动作请求和停止/暂停等命令通道；
- MOS 负责相机、地图、位姿和其他传感器观测的数据通道；
- 设备控制器仍负责实时运动控制、互锁、急停和断联后的本地安全策略。

因此，项目可以把 YOLO、状态估计、规划、执行器和 ROS2 适配器作为可替换模块接入，而不是把所有逻辑硬编码在一个模型调用里。

## 社会仿真的作用

社会仿真是一个可控的实验环境，用来研究：

- 机器人能否根据观察更新关系和任务状态；
- 规范变化或目标冲突时，Agent 是否调整行动；
- 多轮协作、冲突、信任和群体反馈如何影响后续决策；
- 规划失败、视觉失败、社会推理失败能否被区分；
- 运行轨迹和恢复机制是否让行为更可靠、更容易审计。

重点不是先做一个“社会预测引擎”，而是先把**具身 Agent 的设备接入、运行可靠性和行为评测**搭起来，再利用社会场景暴露复杂的决策问题。

## 研究问题

1. 设备观测、视觉检测和任务历史如何共同进入 Agent 状态；
2. 运行时轨迹能否支持失败定位和任务恢复；
3. 社会情境是否会改变机器人规划和行动策略；
4. 如何把导航/控制错误与社会推理错误分开评估；
5. 社会仿真中的行为结论如何迁移到真实设备或更接近真实的环境。

## 与 SocialGrid 等工作的关系

SocialGrid 将规划、任务执行和社会推理放在具身多智能体环境中评估，并用 Planning Oracle 减少导航能力对社会推理评测的干扰。这个思路对本项目的启发是：评测时必须拆分“机器人没走到”和“机器人没有理解社会证据”这两类失败。

## 项目交付状态

Embodied-SocialSim 已完成 5 层系统架构、4 类设备协议对象、Agnes Harness 运行职责、社会仿真循环和 6 轴具身行为评测矩阵。设备型号和实验批次采用独立验收记录，系统框架、协议和评测方法作为项目主体交付。
